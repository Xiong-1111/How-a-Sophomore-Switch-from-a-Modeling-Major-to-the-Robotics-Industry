# ROS 2

**ROS 2（Robot Operating System 2）** 是一套用于构建、部署、运行和维护机器人应用的软件库与工具。  
它不是传统意义上的“操作系统”，而是运行在 Linux 等系统之上的**机器人中间件**。

可以把 ROS 2 理解成各模块之间通信的“管道”：提供消息传递、标准接口，并支持多种编程语言与平台。  
常见组成包括：**节点（Node）**、**话题（Topic）**、**服务（Service）**、**动作（Action）**、**参数（Parameter）**。

> **ROS 与 ROS 2：**  
> ROS 1 是早期版本；现在学习与新项目一般用 **ROS 2**。命令也以 `ros2` 开头。

## Turtlesim

**Turtlesim** 是 ROS 2 的入门小模拟器：一只海龟在窗口里移动，用来演示节点、话题等最基本概念。

启动模拟器（一个终端）：

```bash
ros2 run turtlesim turtlesim_node
```

打开一个新终端，运行一个新节点来控制第一个节点中的海龟

```bash
ros2 run turtlesim turtle_teleop_key
```

## Nodes（节点）

**节点**是 ROS 图里的一个计算单元，通常对应一个独立功能（例如：仿真窗口、键盘控制、相机驱动）。  
每个节点应尽量只做一件逻辑上完整的事。

节点可以：

- **发布 / 订阅话题**：持续收发数据
- **当服务客户端或服务端**：请求一次、返回一次结果
- **当动作客户端或服务端**：下发耗时任务，过程中有反馈，可取消
- **读写参数**：运行时配置，不必改代码

节点之间主要通过四种机制协作：**话题、服务、动作、参数**。  
前三种是通信；**参数**更偏向节点自身的配置（也可被其他节点读写）。

启动节点：

```bash
ros2 run <package_name> <executable_name>
```

含义：运行某个功能包里的可执行文件。例如 `turtlesim` 包中的 `turtlesim_node`。

### 用命令行查看节点

列出当前节点：

```bash
ros2 node list
```

查看某个节点的详细信息（发布/订阅的话题、服务等）：

```bash
ros2 node info <node_name>
```

### 重映射节点名称

重映射功能允许将默认节点属性（例如节点名称、主题名称或服务名称）重新分配给自定义值，而不改源码。

```bash
ros2 run turtlesim turtlesim_node --ros-args --remap __node:=my_turtle
```

这会**再启动一个** Turtlesim 节点，名字为 `my_turtle`，并再弹出一个窗口。  
它**不会**重命名已经在运行的 `/turtlesim`。

## Interfaces（接口）

ROS 2 应用主要通过三类接口通信：**话题、服务、动作**。

接口用简化的描述语言定义，称为 **IDL（Interface Definition Language）**。  
日常还会见到 `.msg`、`.srv`、`.action` 文件；工具会据此自动生成 C++、Python 等语言的代码，保证两端类型一致。

## Topics（话题）

话题是 **发布 / 订阅** 模型，适合**持续数据流**（速度指令、传感器、图像等）。

- 节点把数据 **publish** 到某个话题
- 其他节点 **subscribe** 该话题来接收
- 发送与接收解耦：谁先谁后都可以，支持 **多对多**
- **发布方决定何时发**；订阅方在数据到来时走回调

需要满足：

1. **话题名要一致**，且 **消息类型要一致**（发的是字符串，收的也必须是同类型）。ROS 2 里 **QoS** 也要匹配，否则可能收不到。
2. 同一节点可以订阅多个话题，也可以发布多个话题。
3. 同一话题可以有多个发布者、多个订阅者。


**3. 打印话题实时内容**

```bash
ros2 topic echo <topic_name>
```

例如：`ros2 topic echo /turtle1/cmd_vel`

**4. 查看某话题的发布者 / 订阅者数量**

```bash
ros2 topic info <topic_name>
```

**5. 更详细信息（含 QoS）**

```bash
ros2 topic info /turtle1/cmd_vel --verbose
```

可看到：发布者与订阅者的节点名和命名空间、话题类型、QoS 配置。

**6. 手动往话题发一条消息**

```bash
ros2 topic pub <topic_name> <msg_type> '<args>'
```

示例（让海龟转圈，需按实际发行版调整字段）：

```bash
ros2 topic pub /turtle1/cmd_vel geometry_msgs/msg/Twist "{linear: {x: 2.0, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 1.8}}"
```

## Services（服务）

服务是 **请求–响应（call-and-response）**：客户端向服务端发请求，服务端计算后返回结果。

- 只在被**明确调用**时才交换数据
- 适合“问一次、答一次”、需要较快返回的操作（改背景色、清空轨迹等）
- **不适合**图像、激光那种连续数据流（那是话题的工作）

常用命令：

```bash
ros2 service list
ros2 service type <service_name>
ros2 service call <service_name> <srv_type> '<args>'
```

Turtlesim 示例：清空画布

```bash
ros2 service call /clear std_srvs/srv/Empty
```

## Actions（动作）

**动作**是耗时较长的远程调用：有反馈，也可以取消或被新目标抢占。

例如上层状态机让导航去某个航点，可能要几秒甚至几分钟。期间导航可回报已走距离；上层也可以中途取消。

三个部分：

| 部分 | 作用 |
|------|------|
| **Goal（目标）** | 客户端告诉服务端要做什么，服务端会应答是否接受 |
| **Feedback（反馈）** | 执行过程中服务端持续汇报进度 |
| **Result（结果）** | 任务结束时返回最终结果 |

和 **Service** 的差别：服务是短请求；动作适合长时间任务，并且过程可反馈、可取消。

Turtlesim 里旋转一圈属于动作，例如 `/turtle1/rotate_absolute`。

## Parameters（参数）

**参数**是节点的配置项（键值对：名字 + 数值），可在启动时或运行中修改，不必改代码。

寻址可包括：节点名、节点命名空间、参数名；参数命名空间可选。

常用命令：

```bash
ros2 param list
ros2 param get <node_name> <param_name>
ros2 param set <node_name> <param_name> <value>
```

Turtlesim 示例：改背景颜色相关参数（具体名字以 `ros2 param list` 为准）。

节点还可以注册三种**可选**回调，在参数即将或已经改变时收到通知：

1. **预设参数回调**（`add_pre_set_parameters_callback`）  
   收到待修改的 `Parameter` 列表，无返回值。可在这里增删改条目。例如：`parameter1` 变了，顺带改 `parameter2`。

2. **设置参数回调**（`add_on_set_parameters_callback`）  
   收到不可变的参数列表，返回 `rcl_interfaces/msg/SetParametersResult`。用于**检查并允许/拒绝**这次修改。

3. **设置后回调**（`add_post_set_parameters_callback`）  
   参数已经成功生效后调用，无返回值。用于根据新参数更新节点内部状态。

## 对照小结

| 机制 | 模型 | 适合什么 |
|------|------|----------|
| Topic | 发布 / 订阅 | 连续数据（速度、传感器） |
| Service | 请求 / 响应 | 短时、一次性调用 |
| Action | 目标 + 反馈 + 结果 | 长时间任务，可取消 |
| Parameter | 键值配置 | 改行为、不改代码 |
